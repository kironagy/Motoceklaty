# المرشد

ريسورس قراءة فقط في `/admin/guide`. الوصول من القائمة والرابط والتفاصيل مقصور على حسابات **Staff** ذات الرقمين **25 و27** داخل حارس `filament`، مهما كانت صلاحيات أي حساب آخر.

## التفعيل

بعد رفع الملفات:

```sh
php artisan migrate --force
php artisan optimize:clear
```

أعد تشغيل عمال الطوابير طويلة التشغيل لاستقبال مزود الخدمة الجديد. لا يحتاج الريسورس مكتبة إضافية. الجدول مستقل عن سجل Spatie الحالي.

## التغطية

- يسجل أحداث Eloquent للإضافة والتعديل والحذف والاستعادة لكل موديلات التطبيق، بما فيها العمليات التلقائية؛ يسجل اسم الفاعل ونوع حسابه ورقمه، السجل المتأثر، الوقت، والحقول القديمة والجديدة. التعديل بلا تغييرات فعلية لا ينشئ حدثًا.
- يسجل الدخول والخروج من حراس المصادقة بأسماء أصحاب الجلسات.
- يكمل ذلك ملخص طلبات الويب وAPI التي تنفذ INSERT/UPDATE/DELETE، بما فيها bulk وpivot/sync: أنواع الكتابات والجداول المتأثرة، المسار وأسماء نداءات Livewire. هذا الملخص ليس نجاحًا للعملية كاملة، ولا يحتوي عدد الصفوف أو تفاصيل قبل وبعد لكل صف. قد توجد كتابة قبل فشل خطوة لاحقة أو rollback؛ أحداث الموديلات الموجودة داخل transaction تتراجع معه.
- التحديث المباشر عبر SQL خارج طلبات الويب، أحداث `saveQuietly` خارج طلبات الويب، أو تغييرات ينفذها برنامج خارجي لا تمر بهذه الطبقة. القراءة والتنقل وحدهما لا ينشئان سجلًا.
- لا يسترجع سجلًا تاريخيًا لم يكن مسجلًا قبل التفعيل. لا يوجد تنظيف تلقائي للسجل الجديد.

تفاصيل الأحداث محفوظة كنسخة مستقلة لتبقى بعد حذف الموظف أو العنصر. كلمات المرور والتوكنات ومفاتيح API والحقول المخفية محجوبة؛ لا تخزن أجسام طلبات HTTP أو SQL bindings. فشل التسجيل يبلغ عبر Laravel ولا يوقف العملية الأساسية؛ راقب سجل أخطاء التطبيق.

## التحقق

```sh
php artisan test --filter=GuideTest
```

الاختبارات تبني جداول مصغرة في SQLite بالذاكرة وتغطي حصر الوصول، الإضافة والتعديل والحذف، الدخول والخروج، العمليات الجماعية، حجب الأسرار، وعدم تنفيذ HTML داخل التفاصيل.

## السجل القديم
يستورد الأمر guide:import-history سجلات activity_log وstaff_login_logs وapplication_events والحضور التاريخي إلى المرشد مع حفظ التاريخ الأصلي. كل مصدر له حد استيراد ثابت ومفتاح فريد للسجل؛ إعادة الأمر لا تكرر المستورد ولا تعيد تصنيف الأحداث الجديدة كسجل قديم. لا يحذف أو يعدّل المصادر الأصلية. سجلات الحضور القديمة تثبت الحضور فقط ولا تنسب إدخاله لموظف مجهول. حالات الطلبات تعرض الحالة قبل وبعد، والفاعل يظهر فقط إن كانت هويته محفوظة بشكل صريح.

زر فلتر «السجل القديم فقط» وتفاصيل المصدر يوضحان أصل كل حدث. التسلسل حسب وقت الحدث الأصلي، وليس وقت الاستيراد. الوصول مقفول أيضًا على مستوى استعلام المورد نفسه للرقمين 25 و27 بحارس filament، حتى مع صلاحية is_hitler أو أدوار كاملة لمستخدم آخر.

تسجل طبقة الطلبات أيضًا تنفيذ أزرار Livewire مثل التنزيل والتصدير حتى لو لم يحدث تعديل بقاعدة البيانات؛ تحديث الشاشة والتنقل لا ينشئان أحداثًا. تظل البرامج الخارجية أو SQL خارج التطبيق وكتابات saveQuietly خارج طلبات الويب غير مغطاة بتفاصيل الصفوف. لا يمكن استرجاع أحداث قديمة لم تكن مسجلة أصلًا.


## العرض المبسّط حسب طلب المستخدم
الواجهة والعدادات والفلاتر تعرض الأشخاص فقط: حسابات Staff غير المعلّمة كبوت، وحسابات User البشرية، مع وجود هوية فاعل محفوظة. لا تعرض عمليات السيرفر أو الفاعل المجهول أو ميتاداتا دخول الموظفين المكررة. تظل السجلات الأصلية محفوظة في الجدول. الأعمدة هي الموظف والعملية والعنصر والتغيير والوقت؛ الملخص عربي مع القيم السابقة والجديدة، والمعلومات التقنية داخل قسم مغلق بالتفاصيل. تقلّل طبقة الطلبات تكرار ملخص عام بعد تسجيل تغييرات الموديلات بالفعل.

تم تفعيل الداشبورد فقط وفق اختيار المستخدم، ولم تتم إعادة تشغيل عمال واتساب القائمة. يحمّل هؤلاء مزوّد التسجيل الجديد عند إعادة تشغيلهم الطبيعية لاحقًا؛ لا نفترض تسجيل عملياتهم القديمة داخل الذاكرة قبل ذلك.


العرض الافتراضي أصبح «تغييرات الموظفين» للإضافة والتعديل والحذف والاستعادة، وتبويب مستقل للدخول والخروج، وتبويب لكل تحركات الأشخاص. الصفوف العامة غير المفهومة لا تدخل العرض، ويظهر اسم العنصر والتغيير بالعربية. تغييرات الصور تظهر كـ«غيّر الصورة» بدل مسارات الملفات، وكود الحالة يترجم للعربية. سجلات السيرفر الأصلية باقية للتشخيص لكنها ليست ضمن واجهة المرشد أو عداداتها.


التحقق النهائي: نجح 12 اختبارًا و62 تحققًا على SQLite بالذاكرة، تشمل قفل الوصول، استيراد السجل القديم بدون تكرار، إخفاء السيرفر والبوتات، صياغة الأسعار والحالات بالعربية، حجب الأسرار ومنع تكرار ملخص العملية. تحقق السيرفر أثبت صفر صفوف نظام في استعلام العرض. لم تُنفذ إعادة تشغيل لعمال واتساب احترامًا لاختيار المستخدم.
